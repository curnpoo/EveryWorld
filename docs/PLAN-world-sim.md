# Plan: procedural climate, weather and storms

Status: PLAN ONLY, nothing implemented. Atmosphere, stars and space visuals: `PLAN-space-visuals.md`. Performance: `PLAN-perf.md`.
Map base done: satellite globe (EOX Sentinel-2) with OSM roads/borders burned into the tiles (`globe.rs`, `maprender::overlay_on_imagery`); the climate overlay is still to do.

## Decisions (user)
- Keep real Earth (terrain, coasts, OSM cities). Weather and climate are procedural, NOT real Earth weather and not live data.
- Time: normal Earth time (sun, moon, planets, seasons) for now.
- Everyone sees the same weather (future multiplayer): weather is a pure function of (world seed, UTC time), never of per-client state.
- Personal use only (licensing of imagery is not a constraint yet; revisit before sharing).
- Hurricanes/tornadoes are about as rare as on Earth, but globally there is nearly always something happening somewhere. Physics-based: no hurricane over North Dakota; tornadoes need the real ingredients (instability + shear); strong mountain wind can spawn vortices.
- Map shows satellite imagery with a climate overlay (clouds, precip, wind, highlighted storms). Spawn near a storm from the map.

## Architecture
New crate `ed_climate` (no Bevy dependency so it runs on worker threads and is unit-testable; the Bevy side is thin glue in `ed_game`). Layers, bottom up:

1. **Climate base** (analytic, deterministic): insolation by lat/day-of-year, temperature (lapse rate 6.5 C/km), pressure belts and prevailing winds (Hadley/Ferrel/polar cells + Coriolis), saturation humidity (Clausius-Clapeyron), orographic lift (windward rain, lee shadow), sea-surface temperature field with a seasonal lag. Gives believable deserts, monsoons, rain shadows.
2. **Synoptic grid** (~1-2 degree): advected heat/moisture/pressure (toy GCM / shallow water) giving fronts, highs/lows. Must be random-access in time: spin up from a cached climatological state at launch (seconds on a worker thread) and fast-forward to "now" from a fixed epoch with checkpoints, so every client reaches the identical state. Use fixed-point or strictly ordered float math to keep it deterministic across machines.
3. **Storm records** (the truth): a small struct per event: kind, position, track, radius, intensity, birth/death time. Generated by a seeded process evaluated against layers 1-2:
   - Hurricane: SST > ~26.5 C, latitude 5-20 degrees, low shear, away from the equator (Coriolis); tracks steered by the grid winds, decays over land/cold water. Holland wind profile.
   - Tornado/supercell: high CAPE-like instability + wind shear; Rankine vortex; short lived, small.
   - Mountain wind vortices: strong flow over steep terrain triggers rotors/dust devils/tornado clusters.
   - Also: thunderstorms+lightning, sandstorms (dry, windy, bare soil), blizzards, tsunamis (seismic event + shallow-water wave to coast).
4. **Local realization**: near a storm, a generator builds detail (wind field, funnel, rain bands, debris, cloud shapes) FROM the record. It never writes back, so map and ground always agree. `clouds.rs`, `ground_scatter`, foliage and vehicles read a `WeatherSample` (wind, rain, snow, visibility, cloud cover, nearby vortices).

## Map
- Base: satellite imagery (NASA Blue Marble/GIBS global; Sentinel-2 cloudless for detail), cached like vector tiles. Also used as the color source for distant terrain.
- Overlay: climate grid as textures (clouds, precip, temperature, wind arrows) + storm markers/tracks. Tornadoes are markers with labels, hurricanes drawn as spirals. Pick a storm -> spawn near it.

## Milestones
1. `ed_climate` layer 1 + `WeatherSample` API + tests (known physical checks: Sahara dry, Amazon wet, rain shadow behind a ridge).
2. Layer 2 grid with deterministic spin-up; test same seed/time -> identical state.
3. Storm record generator (hurricane first), tests that none form outside valid conditions.
4. Map overlay + satellite base.
5. Local realization: hurricane wind/rain, then tornado, sandstorm, tsunami.
6. Hook weather into clouds, sky, ground, foliage sway, vehicles.
