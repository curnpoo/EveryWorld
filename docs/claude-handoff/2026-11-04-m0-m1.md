# Claude handoff: M0 finish + M1 start (branch `perf/m0-m1`)

Built and unit-tested in a Linux cloud container (no Mac, no real GPU). Nothing here has been measured on Metal yet. The test pass below is what decides whether M0's exit criterion (45+ fps steady, no frame > 50 ms after load) is met.

## What changed

### M0 (in Bevy)
| Item | Where | Notes |
|---|---|---|
| 2 shadow cascades | `sky.rs` `setup_sky` | 40 m near cascade, 700 m far. Was 3 (25 m / ... / 700 m). |
| Env map only on change | `sky.rs` `refresh_env_map`, patched `vendor/bevy_pbr` (`light_probe/generate.rs` `EnvironmentMapRefresh`, `atmosphere/environment.rs`) | The atmosphere probe pass and the env-map downsample + filter passes now run only when the sun moves > 0.3°, altitude changes > 3% (min 50 m), cloud sun factor changes, or the probe is re-added (pause menu). 3 frames per refresh. Was every frame (~2 ms). |
| Shared terrain material | `ground_material.rs` `SatPool`, `shaders/terrain.wesl` `sample_sat`, `streaming.rs` | Satellite colour moved from one material + one image per tile into 3 fixed texture arrays (512 px x 40, 256 px x 96, 128 px x 192 layers; 76 MB total). The layer index rides on the terrain entity's `MeshTag`. Uploads go straight to the GPU array with `write_texture`. All terrain now batches under one material. **Also fixes a bug:** per-tile material copies never got the floating-origin UV offset update, so ground textures on streamed tiles jumped after travelling > 8 km. |
| Budgeted, staged tile apply | `streaming.rs` `apply_tiles`, `ed_runtime::budget` | Tiles spawn in stages (base + terrain, placements, building chunks one at a time, tree chunks one at a time) under a per-frame cost budget (`EW_APPLY_BUDGET`, default 250 units, ~1 unit per entity or 10k tris) plus a 4 ms cap. A tile stays hidden until complete, so the coarse tile keeps covering the area. Cheap coarse tiles now apply several per frame; heavy ones spread over frames. Tree far meshes are converted on the worker now, not the main thread. |
| Far trees out of shadows | already true for far leaf cards | Unchanged. |

### M1 (started): `crates/ed_runtime` (engine-free, 19 unit tests)
| Module | What |
|---|---|
| `jobs` | Keyed thread pools: priority (lowest first), re-rank while queued, cancel, one entry per key, panics reported. |
| `budget` | `FrameBudget`: cost units + wall clock, first item always runs. |
| `residency` | `Lru`: least-recently-seen with a cap. |
| `view` | Cone test with a tile's real height range. Fixes tiles vanishing above ~4 km ground (Altiplano, Tibet) and when looking up at tall peaks (Matterhorn from Zermatt at 30°); tests reproduce both with the old test. |
| `scheduler` | Build priority (visible first, prefetch in the direction of travel above ~50 m/s) and hole-free retire, linear time, aware of what's in view. |

`streaming.rs` now runs on it:
1. **IO pool** (8 threads) downloads source tiles into the disk cache (`tilegen::prefetch`, new `prefetch` fns in `ed_data`). Network waits no longer hold build threads.
2. **CPU pool** (cores - 3, max 8) runs `tilegen::build` + mesh/collider prep. Off Bevy's shared async pool, so ground cover and building detail no longer queue behind whole-tile builds.
3. Stale queued tiles are cancelled every select (4 Hz); queued ones are re-ranked as you move.
4. **Off-screen tiles stay loaded** while still in the LOD set (up to `EW_RESIDENT_TILES`, default 192, oldest-unseen evicted). Turning around no longer rebuilds the street behind you. Only visible tiles (plus the ground right around you) are *built*.

Not done in M1: tiles are still entity trees ("tiles stop being entities"). That needs the GPU-resident path from M2 to be worth it.

### Not done from M0, on purpose
- **Pipeline pre-warm.** The likely cause of the 3-6 s settings stall: the AO and TAA toggles (`menu.rs` `apply_graphics`) add/remove camera components, which changes every material's pipeline key, so every material re-specializes. Pre-warming needs either a second hidden camera with the other key (21 systems assume one `Camera3d`) or a `bevy_pbr` patch that keeps SSAO bound and skips its dispatch. Confirm the cause first (test 4 below).
- **Tree impostors.** `PLAN-perf.md` records the user's direction "NO impostors"; `PLAN-native-engine.md` M0 lists them. Needs a decision.
- **Clouds ½ res.** Measured 33.3 vs 33.5 fps with clouds off: no gain while vertex bound. Revisit after M2.

## Mac test pass (about 15 minutes)

Use the same scene as the plan's table (Ohio suburb, 67% render scale) plus Zermatt. Compare against `main` at the same spot.

```bash
git checkout perf/m0-m1
EW_PERF=1 EW_PERF_OUT=perf_m0.csv cargo run --release -- --place "Zermatt"
```

1. **Steady fps** (stand still 30 s after load): `fps`, `p99_ms` in the CSV. Target 45+.
2. **Streaming hitches**: spawn, then walk/fly for 60 s. `max_ms` should stay under 50 after load. If spikes remain, lower `EW_APPLY_BUDGET` (try 120); if loading feels slow, raise it (try 500). The new CSV columns `io_jobs,build_jobs,applying` show where tiles wait.
3. **Turn around** at street level a few times: tiles behind you should not reload (debug stats, `I`/`F3`: `tiles N loaded` stays flat, `pending` stays ~0).
4. **Settings stall**: toggle only AO in the pause menu, then only Bloom, then only Shadows. If only AO (and TAA) stall, the pipeline-key theory holds.
5. **Visual checks**:
   - Satellite colour on distant terrain and water looks as before (wrong layer = tiles with another tile's colours; missing = flat navy/green). Debug stats show `satellite layers free a / b / c`; if any hits 0, raise its count in `SAT_CLASSES`.
   - Ambient light follows time-of-day scrubbing (`[` `]`) without lag; no black ambient right after spawn or after leaving the pause menu.
   - Shadows near the player still crisp at 2 cascades.
   - High ground: `--lat -16.5 --lon -68.15` (La Paz) and somewhere on the Altiplano above 4 km; look level and up at peaks. No missing tiles.
6. **Floating origin**: fly > 8 km in one direction; ground textures must not jump.

If something looks wrong, the pieces are independent commits on this branch, so they can be reverted one by one.

## Later the same day: tree impostors + tiles as data

The user approved impostors for trees ("as far as makes sense"), and asked for the "tiles stop being entities" half of M1.

### Tree impostors (M0)
| Piece | Where |
|---|---|
| Atlas bake | `ed_world::trees::impostor`: CPU rasterizer renders every species variant (23 kinds x 3) from 8x8 hemi-octahedral views, 32 px frames (4x supersampled), albedo + tree-local normal, coverage-preserving mips. ~5 s in release on 4 cores, on a background thread at startup (`impostors.rs`); impostors draw nothing until it lands. |
| Per-tile mesh | `impostor::build_mesh`: one quad per tree (sphere centre, radius, atlas layer, axis, thinning rank, the tile's kept share, near cut-off). Built on the tile worker. |
| Shader | `shaders/impostor.wesl`: billboards toward the camera, picks the nearest view frame, thins with distance (share shown = (1000 m / d)^2), grows survivors up to 6x so canopy cover holds, fades trees under ~1.5 px. Same vertex code in main pass and prepass (depth, normals, motion vectors). No shadows. |
| Where trees exist | z10+ tiles now (was z13+). Caps: z14 9,000, z12-13 6,000, z11 5,000, z10 4,000 (`tilegen.rs`). Coarse tiles carry impostors only. |
| LOD chain | impostor -> leaf cards per chunk (z14 only, within `CARD_RANGE_M` = 800 m) -> full trees (within 230 m). The old 1-in-4 / 1-in-16 thinned card bands are gone (impostors replace them). |

"As far as makes sense": a 10 m tree is ~1 px at ~11 km on a 1280 px wide 60° view. With growth (up to 6x) trees stay visible as canopy texture to roughly 20-30 km; past that each tree is sub-pixel and the satellite colour (a photo of the same forest) carries it. From orbit you see forests as colour, which is what they look like from there.

### Tiles stop being entities (M1, Bevy form)
A tile is now about 10 entities, whatever its content:
- terrain, water, roads (as before);
- library placements merged into one mesh + one compound collider (`library::merge_placements`, worker) instead of one entity + rigid body per prop (meshlet A/B path unchanged);
- building LOD merged per material for the whole tile + one trimesh collider (`streaming::merge_lod`) instead of chunk x material entities;
- one impostor entity for all trees;
- a `TreeChunks` holder: leaf-card chunks and full trees become entities only near the camera (`foliage::stream_tree_chunks`), card meshes upload on first approach;
- a `NearMeshes` holder for rock chunks (`near_chunks.rs`, entities within 500 m).

Building detail needs per-chunk LOD to hide the chunk it replaces, so a tile **explodes** its merged LOD into chunk entities (prepared on a worker, spawned 8 per frame) before its first detail chunk, and **implodes** back after 8 s with nothing near (`streaming::Explode`). Only the tiles around the player are ever exploded.

Measured in the cloud container (software Vulkan: counts are meaningful, absolute fps are not), same camera, old build vs new:

| Scene | Entities | Visible meshes | Load to idle |
|---|---|---|---|
| Zermatt village, 120 m AGL | 16,503 -> 2,166 | 4,233 -> 890 | 178 s -> 73 s |
| Zermatt, 4 km | 12,892 -> 1,334 | 2,188 -> 117 | 146 s -> 50 s |
| Black Forest, 3 km | 7,397 -> 1,247 | 96 -> 108 | 82 s -> 26 s |

Resident triangles dropped slightly (20.9M -> 19.5M at the village). Screenshots match the old build except for more distant trees.

Far impostors fade toward the satellite colour under each tree (`TreeInstance::tint`, alpha = from satellite) from 600 m to 3 km, keeping their own shading. Without it, lit crowns showed as light speckles on the dark photo of dense forest.

### Mac checks for this part
1. **Forest look at distance**: fly over a forested valley (Zermatt, Black Forest `--lat 48.0 --lon 8.2`) at 300 m, 3 km, 10 km AGL. Trees should fade into the satellite colour, not pop or leave bald hills. Tune `FULL_M`, `GROW_MAX`, `MIN_PX` in `impostors.rs`.
2. **Card / impostor seam** around 650-950 m: no ring where trees vanish or double in size.
3. **Walking into town**: building detail still swaps in; no flicker when a tile explodes (merged and chunk LOD overlap for a few frames) or implodes.
4. **Physics**: drive into a street light and a building on a fresh tile (merged colliders).
5. `perf.csv` `entities` column should stay roughly flat while flying.
